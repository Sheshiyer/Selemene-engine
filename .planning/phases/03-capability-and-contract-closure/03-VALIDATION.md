# Phase 3 — Validation Strategy

> Every plan task has a focused automated receipt. The final gate consumes the same receipts in dependency order and remains database-free.

Plan set: **27 plans**, **54 tasks**, **13 waves**. Plans `03-03b` and `03-20b` through `03-20f` are the added sequential SDK-build and documentation-parity slices.

## Test Infrastructure

| Property | Value |
|----------|-------|

Plan 21's final receipt map must also invoke and map these focused observations: `cd ts-engines && bun test src/server/__tests__/registry-authority.test.ts src/server/__tests__/capability-route.test.ts && bun run typecheck` (D-01, D-03, D-05; T3-01, T3-03, T3-05), `cd python-services && uv run --locked --extra dev python -m pytest tests/test_capability_health.py tests/test_biofield_health.py tests/test_mediapipe_health.py -q --tb=line` (D-01, D-02, D-03, D-05; T3-01, T3-02, T3-03, T3-05), and `cargo test -p noesis-sdk -p noesis-tui --locked` (D-01, D-02, D-03; T3-01, T3-03, T3-05, T3-08). Their exact source/test paths are read before the gate map is written, and all three receipts are retained in the single locked `gate:contracts` invocation.

The existing `python-services` locked environment is required: Plan 01 must prove pytest, httpx, FastAPI, NumPy, OpenCV and MediaPipe are available through `uv run --locked --extra dev` before any Universal, Hermes or gate:contracts suite runs. If that preflight fails, Plan 01 fails closed before high-threat suites execute. A missing locked import is an environment failure; ambient Python cannot mask it.

## Sampling Rate

- Run each task's focused command after its implementation.
- At each wave boundary run only the wave's focused targets; do not run `pnpm run gate:contracts` between waves.
- Plan 21 runs exactly one `pnpm run gate:contracts` receipt after all focused waves, then the single database-free full gate and `git diff --check`.
- Run the one database-free full gate only after the focused `test_gate_wiring.py` receipt and all predecessor plans are complete.
- Keep every negative case in the focused command: wrong/absent auth, malformed input, unsupported operation, path injection, missing observations, zero-call rejection, bounded errors, and workflow failure conservation.
