# Phase 4 Plan 01: Tarot semantic truth pilot

## Goal

Extend the already-selected Tarot pilot from a partial provenance field into a fixture-driven deterministic truth receipt, while recording the reduced scope for generated, fallback, and unavailable modes that Tarot does not currently offer.

## Scope

- Governing work: #897, ENG-01, ENG-02, W3E Tarot slots 01–30.
- Pilot: `ts-engines/src/engines/tarot` because capability discovery and existing tests are green.
- Allowed edits: Tarot tests, Tarot fixtures, and the Phase 4 evidence note.
- Excluded: provider generation, remote issue mutation, consumer repositories, and unrelated engines.

## Tasks

1. Add a failing fixture-driven replay test for a fixed Tarot input/seed.
2. Add the smallest Selemene-owned JSON fixture needed to make the test green.
3. Verify provenance, semantic card identity, replay stability, and invalid-input rejection.
4. Record that Tarot is deterministic/local-only in this slice; generated/fallback/unavailable states remain explicit follow-up surfaces for engines that actually expose them.

## Verification

```bash
cd ts-engines
bun test tests/tarot_truth_fixture.test.ts tests/tarot_provenance.test.ts
bun run typecheck
```

## Exit condition

The pilot has a reproducible fixture and no claim is made that Tarot's local deterministic path proves provider-generated or sidecar-unavailable behavior.
